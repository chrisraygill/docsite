Pick the guide that matches how you're building. Each guide is self-contained — you don't need to complete the general quickstart first.

## Start with your app platform

<Lang lang="js">

If you're building a web app or full-stack TypeScript application, start with one of these guides:

- [Next.js App Router](/docs/frameworks/nextjs-app-router) for full-stack React apps using route handlers and the first-party Genkit Next.js integration.
- [Next.js Pages Router](/docs/frameworks/nextjs-pages) if you're adding Genkit to an existing `pages/` app and want the best migration path.
- [SvelteKit](/docs/frameworks/sveltekit) for full-stack Svelte apps using SvelteKit API routes and the Genkit fetch handler.
- [Nuxt](/docs/frameworks/nuxt) for full-stack Vue apps using Nitro server routes and the Genkit fetch handler.
- [TanStack Start](/docs/frameworks/tanstack-start) for full-stack React apps using TanStack Router with Vinxi API routes.
- [Astro](/docs/frameworks/astro) for content-driven sites using Astro SSR with API routes and the Genkit fetch handler.
- [Angular](/docs/frameworks/angular) for Angular SSR and hybrid-rendered applications.
- [React (Vite)](/docs/frameworks/react) for client-side React apps that connect to a standalone Genkit backend.
- [Remix](/docs/frameworks/remix) for full-stack React apps using Remix resource routes and the Genkit fetch handler.
- [Express](/docs/frameworks/express) for existing Node.js backends or custom API servers.
- [Hono](/docs/frameworks/hono) for Web-standard request and response handling across Node.js and edge-style runtimes.
- [Fastify](/docs/frameworks/fastify) for Fastify servers that want to expose Genkit flows through the fetch plugin.
- [NestJS](/docs/frameworks/nestjs) for NestJS applications that want to expose Genkit flows through a controller.
- [Deploy with Firebase](/docs/deployment/firebase) if you want the most integrated Google-first serverless path.
- [Deploy to any platform](/docs/deployment/any-platform) if you're building your own Node.js hosting setup.

If you're not ready to choose a framework-specific path yet, start with the [Quickstart](/docs/get-started), then continue into [Creating flows](/docs/flows) and [Generating content](/docs/models).

</Lang>

<Lang lang="go">

For Go projects, Genkit is a great fit when you want a low-level, model-agnostic SDK behind your own services:

- [Gin](/docs/frameworks/gin) for Gin-based REST APIs and web services.
- [Echo](/docs/frameworks/echo) for Echo servers with built-in middleware support.
- [Chi](/docs/frameworks/chi) for lightweight, composable routers using `net/http`.
- [Deploy with Cloud Run](/docs/deployment/cloud-run) for the most direct managed deployment path.
- [Deploy to any platform](/docs/deployment/any-platform) for custom servers and self-managed environments.

If you're not ready to choose a framework-specific path yet, start with the [Quickstart](/docs/get-started), then continue into [Creating flows](/docs/flows) and [Generating content](/docs/models).

If you're building a Go backend for a separate web or mobile frontend, pair this with the [Web client](/docs/frontend/web-client) or [Flutter](/docs/frontend/flutter) guide.

</Lang>

<Lang lang="dart">

For Dart, Genkit supports both client-heavy and full-stack paths:

- [Flutter](/docs/frontend/flutter) for mobile, desktop, and web apps using the Dart client SDK story.
- [Shelf](/docs/frameworks/shelf) for Dart servers that expose flows and APIs directly.
- [Deploy with Cloud Run](/docs/deployment/cloud-run) for managed backend hosting.
- [Deploy to any platform](/docs/deployment/any-platform) for custom Dart deployments.

If you want to get oriented first, start with the [Quickstart](/docs/get-started) and then explore [Calling Genkit from the client](/docs/client).

</Lang>

<Lang lang="python">

For Python, start from the web framework or deployment model you already use:

- [FastAPI](/docs/frameworks/fastapi) for modern APIs, streaming responses, and typed server applications.
- [Flask](/docs/frameworks/flask) for lightweight Python services and flexible server integrations.
- [Django](/docs/frameworks/django) for adding Genkit flows to Django projects using Django Ninja or REST framework.
- [Deploy with Cloud Run](/docs/deployment/cloud-run) for a managed container path.
- [Deploy to any platform](/docs/deployment/any-platform) for custom Python hosting.

If your Python service is powering a separate web or mobile app, also review the [Web client](/docs/frontend/web-client) or [Flutter](/docs/frontend/flutter) guide.

</Lang>

## Choose by application shape

- **App with built-in AI features:** Start with an app integration guide like [Next.js App Router](/docs/frameworks/nextjs-app-router), [SvelteKit](/docs/frameworks/sveltekit), [Nuxt](/docs/frameworks/nuxt), [TanStack Start](/docs/frameworks/tanstack-start), [Astro](/docs/frameworks/astro), [Angular](/docs/frameworks/angular), [React (Vite)](/docs/frameworks/react), [Remix](/docs/frameworks/remix), or [Flutter](/docs/frontend/flutter). Each guide offers two paths — use the framework's own API routes, or connect to a standalone Genkit backend in any language.
- **Standalone server for AI endpoints:** Start with a server integration guide like [Express](/docs/frameworks/express), [Hono](/docs/frameworks/hono), [NestJS](/docs/frameworks/nestjs), [Gin](/docs/frameworks/gin), or [FastAPI](/docs/frameworks/fastapi), then connect a frontend with the [Web client](/docs/frontend/web-client) or [Flutter](/docs/frontend/flutter) guide.
- **Prototype first, architecture later:** Start with the [Quickstart](/docs/get-started), test your flows in the [Developer tools](/docs/devtools), and then move into a framework guide once the feature takes shape.
