Use this guide when your app uses the Next.js Pages Router. You can either expose Genkit flows through a companion server, or connect your Next.js frontend to a standalone Genkit backend written in any language.

## Before you begin

- Node.js v20 or later
- npm

This guide assumes you're already familiar with building Next.js applications.

## Create a project

If you don't already have a Next.js project, create one:

<PackageManagerTabs command="npx create-next-app@latest --src-dir" />

<Lang lang="js">

Genkit works well in Pages Router applications, but the first-party `@genkit-ai/next` route helper is currently designed for the App Router's `route.ts` handlers.

That means the best path depends on how much of your app you want to modernize right now:

- If you want the most integrated Next.js setup for Genkit HTTP routes and client helpers, use the [Next.js App Router](/docs/frameworks/nextjs-app-router) guide.
- If your app is staying on Pages Router for now, you can still define Genkit flows in shared server-side code and expose them through a separate Genkit server layer such as [Express](/docs/frameworks/express) or [Hono](/docs/frameworks/hono).

## When to use this path

This is a good fit when:

- your UI is already built on `pages/`
- you want to add AI features without migrating your entire app first
- you're comfortable keeping Genkit routes in a small companion server or separate backend

## Recommended architecture

For Pages Router apps, the cleanest setup today is:

1. Keep your Next.js app for pages, layouts, and frontend logic.
2. Define Genkit flows in shared TypeScript modules.
3. Expose those flows from a Genkit-friendly server runtime such as Express or Hono.
4. Call those flow endpoints from your Next.js frontend.

This gives you a smooth upgrade path:

- you can ship Genkit features now
- you can keep your existing Pages Router app structure
- you can move individual APIs to App Router later if you choose

## Define your recipe flow

Create `src/genkit/recipeGeneratorFlow.ts`:

```ts title="src/genkit/recipeGeneratorFlow.ts"
import { googleAI } from '@genkit-ai/google-genai';
import { genkit, z } from 'genkit';

const ai = genkit({
  plugins: [googleAI()],
  model: googleAI.model('gemini-flash-latest', {
    temperature: 0.8,
  }),
});

const RecipeInputSchema = z.object({
  ingredient: z.string().describe('Main ingredient or cuisine type'),
  dietaryRestrictions: z
    .string()
    .optional()
    .describe('Any dietary restrictions'),
});

const RecipeSchema = z.object({
  title: z.string(),
  description: z.string(),
  prepTime: z.string(),
  cookTime: z.string(),
  servings: z.number(),
  ingredients: z.array(z.string()),
  instructions: z.array(z.string()),
  tips: z.array(z.string()).optional(),
});

export const recipeGeneratorFlow = ai.defineFlow(
  {
    name: 'recipeGeneratorFlow',
    inputSchema: RecipeInputSchema,
    outputSchema: RecipeSchema,
  },
  async (input) => {
    const prompt = `Create a recipe with the following requirements:
      Main ingredient: ${input.ingredient}
      Dietary restrictions: ${input.dietaryRestrictions || 'none'}`;

    const { output } = await ai.generate({
      prompt,
      output: { schema: RecipeSchema },
    });

    if (!output) throw new Error('Failed to generate recipe');
    return output;
  },
);
```

## Expose the flow from a companion server

Create `src/server/index.ts` to expose the flow using Express:

```ts title="src/server/index.ts"
import express from 'express';
import { expressHandler } from '@genkit-ai/express';
import { recipeGeneratorFlow } from '../genkit/recipeGeneratorFlow';

const app = express();
app.use(express.json());

app.post('/recipeGeneratorFlow', expressHandler(recipeGeneratorFlow));

app.listen(8080, () => {
  console.log('Genkit server listening on http://localhost:8080');
});
```

You can also choose [Hono](/docs/frameworks/hono) if you want a lightweight fetch-based server that can target multiple runtimes.

## Call your flow from the frontend

Update `src/pages/index.tsx`:

```tsx title="src/pages/index.tsx"
import { useState } from 'react';
import { runFlow } from 'genkit/beta/client';

export default function Home() {
  const [ingredient, setIngredient] = useState('avocado');
  const [dietaryRestrictions, setDietaryRestrictions] = useState('vegetarian');
  const [recipe, setRecipe] = useState<any>(null);

  async function generateRecipe() {
    const result = await runFlow({
      url: 'http://localhost:8080/recipeGeneratorFlow',
      input: { ingredient, dietaryRestrictions },
    });

    setRecipe(result);
  }

  return (
    <main>
      <h1>Recipe generator</h1>
      <input
        value={ingredient}
        onChange={(e) => setIngredient(e.target.value)}
      />
      <input
        value={dietaryRestrictions}
        onChange={(e) => setDietaryRestrictions(e.target.value)}
      />
      <button onClick={generateRecipe}>Generate recipe</button>
      {recipe && <pre>{JSON.stringify(recipe, null, 2)}</pre>}
    </main>
  );
}

Start the Next.js app and the companion server separately:

```bash

<PackageManagerTabs command="genkit start -- npx tsx --watch src/genkit/recipeGeneratorFlow.ts" />

## Test your flow

With the companion server running, call your flow over HTTP:

```bash
curl -X POST http://localhost:8080/recipeGeneratorFlow \
  -H "Content-Type: application/json" \
  -d '{"data":{"ingredient":"avocado","dietaryRestrictions":"vegetarian"}}'
```

You should receive a structured recipe in the response.

The Genkit CLI is required to run the Developer UI. If you followed the installation steps above, you already have it installed.

Run the following command from your project root:

<PackageManagerTabs command="genkit start -- npx tsx --watch src/genkit/recipeGeneratorFlow.ts" />

This starts your app and launches the Developer UI at `http://localhost:4000` by default.

:::note
The command after `--` should run the file that defines or imports your Genkit components. You can use `tsx`, `node`, or other commands based on your setup. Learn more in [developer tools](/docs/devtools).

## Connect to a standalone backend

Since your Genkit backend uses a different language, you'll set up the backend and frontend separately:

1. **Set up your backend** — follow a [server integration guide](/docs/frameworks/overview) for your language to create a Genkit server that exposes flows as HTTP endpoints.
2. **Call flows from Next.js** — use `runFlow` from the Genkit client library in your pages, pointing to your backend's URL.

### Install the client library

<PackageManagerTabs command="npm install genkit" />

### Call a flow

```tsx title="src/pages/index.tsx"
import { useState } from 'react';
import { runFlow } from 'genkit/beta/client';

export default function Home() {
  const [ingredient, setIngredient] = useState('avocado');
  const [dietaryRestrictions, setDietaryRestrictions] = useState('vegetarian');
  const [recipe, setRecipe] = useState<any>(null);

  async function generateRecipe() {
    const result = await runFlow({
      url: 'http://localhost:3000/recipeGeneratorFlow',
      input: { ingredient, dietaryRestrictions },
    });

    setRecipe(result);
  }

  return (
    <main>
      <h1>Recipe generator</h1>
      <input
        value={ingredient}
        onChange={(e) => setIngredient(e.target.value)}
      />
      <input
        value={dietaryRestrictions}
        onChange={(e) => setDietaryRestrictions(e.target.value)}
      />
      <button onClick={generateRecipe}>Generate recipe</button>
      {recipe && <pre>{JSON.stringify(recipe, null, 2)}</pre>}
    </main>
  );
}
```

Replace `http://localhost:3000` with your backend's address. See the [Web client](/docs/frontend/web-client) guide for streaming and advanced patterns.
